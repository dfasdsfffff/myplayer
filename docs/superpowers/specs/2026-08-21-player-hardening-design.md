# MyPlayer 稳定性与工程化加固设计

## 目标

在不重写播放器架构的前提下，解决当前能够复现或从代码直接证明的四类问题：Windows 构建前置条件不完整、`PacketQueue::serial` 跨线程数据竞争、网络媒体地址泄露到日志、播放列表回退解析重复扫描目录。

## 本轮范围

本轮交付包含：

1. 明确 Visual Studio ATL/MFC 构建前置条件，并固定 vcpkg baseline，避免依赖版本随本机 vcpkg checkout 漂移。
2. 将包队列序列号改为原子状态，让解码器、时钟和刷新线程通过原子快照读取。
3. 统一播放器自有错误日志中的媒体地址脱敏，并覆盖常见认证查询参数。
4. 将 M3U 回退匹配所需的目录文件索引延迟构建一次并复用，避免每个条目重新扫描目录。
5. 为上述行为增加最小、可运行的回归测试，并更新执行记录。

本轮不包含：

- 自动安装或修改 Visual Studio；仓库只声明并验证前置条件。
- 重写 `VideoCtl`、引入新的播放框架或抽象层。
- YUV/NV12 直传、硬件解码或渲染后端替换；这些优化必须由性能数据驱动。
- 大规模 Qt UI 测试体系改造；恢复完整构建后再单独实施真实 Widget 测试。
- 后台目录扫描线程；先消除确定存在的重复扫描，再根据实际卡顿决定是否异步化。

## 设计

### 构建与依赖

保留当前 vcpkg 迁移方向和 SoundTouchDLL C wrapper，不在本轮更换音频变速 API。README 明确 Windows 构建需要 Visual Studio 的 ATL/MFC 组件，因为当前 vcpkg SoundTouch port 在 Windows 上依赖 `atlmfc`。

在 manifest 中加入与当前可用依赖集合匹配的 `builtin-baseline`。构建验证使用新的构建目录，避免旧 `build` 目录中仓库内置 FFmpeg 缓存与新 vcpkg 配置混合。

### 包队列序列号

`PacketQueue::serial` 改为 `std::atomic<int>`。队列内部写入使用 `fetch_add`；外部比较使用 `load`。`Clock` 保存 `std::atomic<int>*`，在 `get()` 中读取当前序列号。包入队时将原子值复制到 `MyAVPacketList::serial`，包自身携带的序列号仍为普通整数。

不增加第二套互斥量，不改变 PacketQueue 的所有权和阻塞协议，也不把无关播放状态全部改为原子变量。

### 网络地址脱敏

播放器自有日志在输出媒体位置前统一调用 `RedactMediaLocation()`。脱敏覆盖 URL authority 中的用户信息，并以大小写不敏感方式识别 `token`、`access_token`、`signature`、`api_key`、`apikey`、`auth` 和 `x-amz-signature`。

FFmpeg 第三方库内部日志不在本轮包装；验收范围是仓库代码主动生成的错误与状态消息不得包含上述凭据值。

### 播放列表回退索引

`ReadM3u()` 继续保持现有解析顺序：直接路径、百分号解码、file URL、EXTINF 标题回退。仅当首次需要标题/文件名回退匹配时，扫描播放列表所在目录并建立大小写无关的候选集合；后续条目复用该集合。

不改变支持的媒体扩展名，不递归扫描播放列表目录，不改变同名候选的现有首个匹配语义。

## 测试策略

所有行为修改遵循红—绿—重构：

1. 网络测试先加入新的敏感键脱敏用例，并验证修改前失败。
2. 核心测试加入原子 serial 与 Clock 接口的编译期/运行时检查，并验证修改前编译失败。
3. 播放列表测试构造多个需要回退匹配的条目，验证解析结果；为证明只扫描一次，将目录索引提取为可测试的局部辅助逻辑或通过明确的索引构建接口测试，不使用源码字符串匹配。
4. 配置修改通过干净 CMake configure 验证。若系统仍缺 ATL/MFC，记录为外部前置条件阻塞，不声称完整构建通过。
5. 最终运行所有能够生成的 CTest，并明确区分通过、失败和未运行。

## 验收标准

- `PacketQueue::serial` 不再以普通 `int` 被跨线程直接读写。
- `Clock` 与 Decoder 使用原子序列号接口，seek/flush 的代次语义保持不变。
- 自有错误日志不输出网络 URL 中的用户密码和已列出的敏感查询值。
- M3U 回退解析对单次导入最多构建一次目录索引。
- README 精确列出 ATL/MFC 前置条件，vcpkg 依赖版本有 baseline。
- 新测试均经历可观察的失败和通过阶段；最终验证结果如实记录。

## 风险与回滚

原子 serial 修改会触及 Clock、Decoder 和 VideoCtl 的多个读取点，但不改变队列数据结构和线程生命周期。若出现兼容问题，可按一个提交整体回滚。

播放列表优化只缓存单次 `ReadM3u()` 调用内的目录信息，不引入长期缓存，因此不存在目录变化后的失效问题。
