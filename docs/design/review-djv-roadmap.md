## 阶段二：多素材与 A/B 对比

本轮按 `FilesModel` 的素材与角色分离、`CompareActions` 的比较模式和 `ReviewCompare` 的 A/B 配置方向实现首批功能，保留本项目 SDK 架构。

- 素材列表只保留路径、工程关联与上次 A 位置；闲置条目不创建解码器。A 切换前必须完成原有保存／放弃／取消流程，撤销栈和区间按单素材会话隔离。
- A 是唯一播放控制与声音来源，B 使用独立静音会话。B 时间为 A 毫秒位置加有符号偏移；不同帧率按经过时间映射，越界不重复旧帧伪装成有效比较。
- 并排、可调擦除／叠加、显示域差分与冻结参考帧；合成不是高位深或 OCIO 线性色彩管线。
- 采用异步请求串联及主时钟校正，不提供 B 独立播放按钮。SDK 普通 seek 仍不保证目标帧，双路播放不保证逐帧锁定。
- 尚未对齐 DJV 的多素材工程持久化、多 B、绝对时间码、旋转擦除及其全部比较模式。v1 工程和恢复继续仅管理当前 A；素材选择、偏移、参考帧仅本次工作区有效。

操作和测试入口见应用 README。

## 阶段三：专业媒体和色彩

扩展源格式抽象、图像序列发现/缺帧策略、有理数时间和帧索引；评估 EXR/DPX、OCIO 依赖与许可证、GPU/内存预算。高位深需要从解码、缓存、变换一直到渲染保持精度，不能把 8-bit SDL 画面加“色彩管理”开关作为实现。连续倒放、严格音视频区间和往返循环需要 Core 专项，不由 UI 定时 seek 模拟。

## 阶段四：高级审阅与交付

绘制标注、波形/缩略图/缓存展示、多轨和 OTIO、第二显示窗口、可移植导出及便携发行。每项需端到端测试和兼容性说明；不预先增加无实际功能的占位按钮。
