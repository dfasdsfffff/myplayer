
## 目前ui界面如何和播放核心通讯

目前 UI 和播放核心是双向通信，但两条方向分开处理：

**1. UI -> 播放核心：通过 `PlaybackController` 发命令**

UI 不直接操作 `VideoCtl`，而是拿到一个控制器：

`MainWid::Init()` 创建 `PlaybackRuntime`，再取出 `PlaybackController`，把它传给 UI 组件使用。

核心链路是：

```text
Qt UI 操作
  -> MainWid / Show / CtrlBar / Playlist
  -> PlaybackController
  -> VideoCtl
```

例子：

```text
CtrlBar::SigPlayOrPause
  -> MainWid lambda
  -> m_playbackController->pause()
  -> VideoCtl::OnPause()
```

相关文件：

- [mainwid.cpp](<./apps/qt_player/mainwid.cpp:105>)
- [playback_controller.h](<./play_core/playback_controller.h:8>)
- [playback_controller_videoctl.cpp](<./play_core/playback_controller_videoctl.cpp:5>)

**2. 播放核心 -> UI：通过 signal 转发事件**

`VideoCtl` 不使用 Qt signals，而是使用 `sigslot`。核心事件先发到 `PlaybackRuntime`，再通过 `PlaybackRuntimeBridge` 转成 Qt signals，并投递回 Qt 主线程。

链路是：

```text
VideoCtl::SigVideoFrame / SigVideoPlaySeconds / SigPauseStat ...
  -> PlaybackRuntime
  -> PlaybackRuntimeBridge
  -> Qt signal
  -> MainWid / CtrlBar / Show / Title / Playlist
```

这个桥接很关键，因为播放核心事件可能来自解码线程、读线程或刷新线程，而 Qt 控件只能在 UI 主线程操作。

相关文件：

- [playback_runtime.cpp](<./play_core/playback_runtime.cpp:37>)
- [playback_runtime_bridge.cpp](<./apps/qt_player/playback_runtime_bridge.cpp:21>)
- [mainwid.cpp](<./apps/qt_player/mainwid.cpp:241>)

视频帧也是这样走的：

```text
VideoCtl::emit_video_frame()
  -> RendererDispatcher::dispatchFrame()
  -> SigVideoFrame(shared_ptr<VideoFrame>)
  -> PlaybackRuntimeBridge::SigVideoFrame
  -> Show::OnVideoFrame()
  -> SDL_UpdateTexture()
  -> SDL_RenderPresent()
```

一句话总结：**UI 发控制命令走 `PlaybackController`，播放核心回传状态/帧走 `sigslot -> PlaybackRuntimeBridge -> Qt signal`。这样 `play_core` 不依赖 Qt，UI 线程也不会被核心线程直接碰到。**

## 是如何传递数据的

主要分三类数据传递：**控制命令、状态事件、媒体帧数据**。

**1. UI -> 播放核心：传递控制数据**

UI 传给核心的不是复杂对象，而是简单参数：

```text
文件路径 string
播放进度 double
音量百分比 double
播放速度 double
循环策略 enum
```

链路：

```text
Qt 控件 signal
  -> MainWid 槽函数/lambda
  -> PlaybackController 方法
  -> VideoCtl 方法
```

例子：

```text
CtrlBar 拖动进度条
  -> SigPlaySeek(double percent)
  -> m_playbackController->seek(percent)
  -> VideoCtl::OnPlaySeek(percent)
  -> VideoCtl::stream_seek(...)
```

播放文件也是类似：

```text
Playlist::SigPlay(QString filePath)
  -> MainWid::OnPlayFile(QString)
  -> m_playbackController->play(filePath.toStdString())
  -> VideoCtl::StartPlay(std::string)
```

`PlaybackController` 本身不保存播放数据，它只是把 UI 命令转发给 `VideoCtl`。

---

**2. 播放核心 -> UI：传递状态数据**

核心播放过程中会主动发事件，比如：

```text
总时长 int
当前播放秒数 int
当前音量 double
暂停状态 bool
播放开始文件名 string
停止完成通知
播放下一首通知
随机播放通知
```

链路：

```text
VideoCtl::Signal
  -> PlaybackRuntime::Signal
  -> PlaybackRuntimeBridge
  -> Qt signal
  -> CtrlBar / Show / Title / Playlist
```

例子：

```text
VideoCtl::SigVideoPlaySeconds(int seconds)
  -> PlaybackRuntime::SigVideoPlaySeconds(seconds)
  -> PlaybackRuntimeBridge::SigVideoPlaySeconds(seconds)
  -> CtrlBar::OnVideoPlaySeconds(seconds)
```

这里 `PlaybackRuntimeBridge` 会用：

```cpp
QMetaObject::invokeMethod(..., Qt::QueuedConnection)
```

把数据投递回 Qt 主线程，避免播放线程直接操作 UI。

---

**3. 视频帧数据：通过 `shared_ptr<VideoFrame>` 传递**

视频帧数据比较大，所以不是复制给 UI，而是用智能指针传：

```cpp
std::shared_ptr<VideoFrame>
```

`VideoFrame` 大概包含：

```text
width
height
bytesPerLine
bgra buffer
```

链路：

```text
video_thread 解码 AVFrame
  -> queue_picture 放入 FrameQueue
  -> LoopThread/video_refresh 决定显示时机
  -> emit_video_frame()
  -> sws_scale 转成 BGRA
  -> RendererDispatcher::dispatchFrame(shared_ptr<VideoFrame>)
  -> VideoCtl::SigVideoFrame
  -> PlaybackRuntimeBridge::SigVideoFrame
  -> Show::OnVideoFrame(shared_ptr<VideoFrame>)
  -> SDL_UpdateTexture
```

所以 UI 最终拿到的是一块已经转换好的 BGRA 图像数据，不需要理解 FFmpeg 的 YUV/NV12 等格式。

---

**4. 音频数据不传给 UI**

音频数据不经过 Qt UI。它在核心内部流动：

```text
ReadThread
  -> audio PacketQueue
  -> audio_thread 解码
  -> audio FrameQueue
  -> SDL audio callback
  -> audio_decode_frame
  -> SDL 输出设备
```

UI 只接收音量、进度、暂停状态这些控制/状态数据，不直接接触 PCM 音频数据。

一句话：**UI 发给核心的是轻量控制参数；核心回给 UI 的是状态事件和 `shared_ptr<VideoFrame>`；音频数据完全留在播放核心内部由 SDL 拉取播放。**


## 播放器核心从打开文件到播放数据的流程

播放器核心从“打开文件”到“真正播放数据”，主流程可以理解成 **5 条链路**：打开文件、读包、解码、音频播放、视频显示。

**总体流程**

```text
UI 选择文件
  -> PlaybackController::play(file)
  -> VideoCtl::StartPlay(file)
  -> VideoCtl::stream_open(file)
  -> 启动 ReadThread
  -> ReadThread 打开媒体文件并读取 AVPacket
  -> AVPacket 分发到 audio/video/subtitle PacketQueue
  -> audio_thread / video_thread / subtitle_thread 解码
  -> 解码后的 AVFrame 放入 FrameQueue
  -> 音频由 SDL audio callback 拉取播放
  -> 视频由 LoopThread/video_refresh 按同步时钟取帧显示
```

核心入口在 [videoctl.cpp](<./play_core/videoctl.cpp:2353>)。

**1. UI 发起播放**

用户打开文件或双击播放列表后，Qt UI 不直接调用 `VideoCtl`，而是走 `PlaybackController`：

```text
Playlist::SigPlay(filePath)
  -> MainWid::OnPlayFile(filePath)
  -> m_playbackController->play(filePath)
  -> VideoCtl::StartPlay(filePath)
```

`PlaybackController` 只是命令转发层，真正进入播放核心的是：

```cpp
VideoCtl::StartPlay(const std::string& strFileName)
```

**2. `StartPlay()` 创建播放会话**

`StartPlay()` 做几件事：

```text
停止旧播放循环
发送 SigStartPlay 通知 UI
调用 stream_open(file)
保存新的 VideoState
启动 LoopThread
```

`VideoState` 是一次播放会话的核心状态，里面包含：

```text
session  文件、读线程、seek/pause/abort 状态
audio    音频流、音频队列、音频解码器、SDL 缓冲
video    视频流、视频队列、视频解码器、SWS 转换上下文
subtitle 字幕流、字幕队列、字幕解码器
clocks   音频时钟、视频时钟、外部时钟
filters  FFmpeg filter graph
```

对应定义在 [video_state.h](<./play_core/video_state.h:125>)。

**3. `stream_open()` 初始化队列和线程**

`stream_open()` 负责创建并初始化 `VideoState`：

```text
new VideoState
初始化 audio/video/subtitle stream index
创建 SoundTouch handle
初始化 FrameQueue
初始化 PacketQueue
初始化音频/视频/外部时钟
设置初始音量
启动 ReadThread
```

关键点是这里会创建三类队列：

```text
audio PacketQueue    压缩音频包
video PacketQueue    压缩视频包
subtitle PacketQueue 压缩字幕包

audio FrameQueue     解码后音频帧
video FrameQueue     解码后视频帧
subtitle FrameQueue  解码后字幕帧
```

**4. `ReadThread()` 打开文件并读 AVPacket**

`ReadThread()` 是媒体读取线程，核心职责是：

```text
avformat_alloc_context()
avformat_open_input()
avformat_find_stream_info()
av_find_best_stream()
stream_component_open(audio/video/subtitle)
循环 av_read_frame()
按 stream_index 把 packet 放进对应 PacketQueue
```

它只负责“读压缩包”，不直接解码。

```text
av_read_frame()
  -> 如果是音频包，放入 audioq
  -> 如果是视频包，放入 videoq
  -> 如果是字幕包，放入 subtitleq
```

这样设计是为了让“文件读取”和“音视频解码”解耦，避免某一边慢了阻塞整个播放器。

**5. `stream_component_open()` 打开具体流**

找到音频/视频/字幕流后，会调用：

```cpp
VideoCtl::stream_component_open(VideoState* is, int stream_index)
```

它会根据流类型做不同处理：

```text
音频流：
  创建 AVCodecContext
  打开 decoder
  初始化 SDL audio device
  启动 audio_thread

视频流：
  创建 AVCodecContext
  打开 decoder
  启动 video_thread

字幕流：
  创建 AVCodecContext
  打开 decoder
  启动 subtitle_thread
```

**6. 音频数据如何播放**

音频链路是：

```text
audio PacketQueue
  -> audio_thread()
  -> Decoder::decode_frame()
  -> audio FrameQueue
  -> SDL audio callback
  -> audio_decode_frame()
  -> swr_convert 重采样
  -> SoundTouch 变速
  -> SDL_MixAudioFormat
  -> 声卡输出
```

注意：音频不是 UI 主动推送播放的，而是 **SDL 音频设备回调主动拉数据**。

也就是：

```text
SDL 需要更多音频数据
  -> 调用 sdl_audio_callback()
  -> callback 调用 VideoCtl::audio_decode_frame()
  -> 从 audio FrameQueue 取解码帧
  -> 转成设备需要的 PCM
  -> 写入 SDL stream
```

所以音频播放核心在播放核心内部完成，UI 只控制音量、暂停、倍速、seek。

**7. 视频数据如何显示**

视频链路是：

```text
video PacketQueue
  -> video_thread()
  -> Decoder::decode_frame()
  -> queue_picture()
  -> video FrameQueue
  -> LoopThread()
  -> video_refresh()
  -> video_display()
  -> emit_video_frame()
  -> sws_scale 转 BGRA
  -> RendererDispatcher
  -> PlaybackRuntimeBridge
  -> Show::OnVideoFrame()
  -> SDL_UpdateTexture()
  -> SDL_RenderPresent()
```

`video_thread()` 负责解码，不负责直接显示。

真正决定“什么时候显示哪一帧”的是：

```text
LoopThread()
  -> video_refresh()
  -> MediaSync::compute_target_delay()
```

它会根据音频时钟、视频时钟和帧 pts 判断：

```text
该等一下
该显示当前帧
该丢帧追赶
播放结束后该停止/下一首/随机
```

**8. 视频帧如何从核心传给 UI**

核心不会把 FFmpeg 原始 `AVFrame` 直接给 UI，而是转成 `VideoFrame`：

```text
AVFrame
  -> sws_scale()
  -> BGRA buffer
  -> std::shared_ptr<VideoFrame>
  -> SigVideoFrame
  -> Qt bridge
  -> Show
```

这样 UI 不需要关心 YUV、NV12、linesize、FFmpeg 生命周期，只拿一块可渲染的 BGRA 图像。

一句话总结：

```text
ReadThread 负责读包；
audio_thread/video_thread 负责解码；
PacketQueue/FrameQueue 负责跨线程缓存；
SDL audio callback 负责拉取音频播放；
LoopThread/video_refresh 负责按同步时钟显示视频；
PlaybackRuntimeBridge 负责把核心状态和视频帧安全传回 Qt UI。
```
